## 研究问题：组织被实现，不等于组织被看见

层级多智能体系统可以通过程序指定角色、委派路径和结果回传机制，却不一定让个别模型调用看到完整的组织。原生角色指令与局部接口可以支持协调执行；但**组织能够运作，并不意味着成员获得了完整的组织信息**。本文因此区分系统实现的组织与实际提供给成员的组织视图。

**当成员获得更广泛的组织视图时，它们参与既有组织的方式会怎样改变？**

论文比较 BASE（系统原生输入）和 ORG-DESC（历史归档标记 V2，额外加入关于既有角色、关系和信息流的静态全局说明）。各对照中的原生角色、工具、路由与执行规则保持不变。ROMA 通过递归任务处理模板组织协作，TalkHier Physics 则采用固定的六角色层级；新增说明描述现有组织，不赋予新的权限，也不提供完整的实时任务树。

按照论文，研究分为两个问题：**RQ1：更广泛的组织视图如何改变既有组织中的执行行为？RQ2：这些执行变化伴随什么计算投入与实际价值？** RQ1 是主线，任务结果和外部评分用于评价行为变化的意义，而不是将成功率提升作为研究目的。

配对实验涵盖 ROMA / SEAL-0（94 题，272 个匹配题目轮次）、ROMA / FRAMES（47 个有效配对问题），以及 TalkHier / MMLU-Pro Physics（94 个有效配对问题）。它们是研究样本，不代表完整基准的总体表现。研究条件与输入边界见[论文](paper/organizational_visibility_preprint.pdf)和[方法](docs/methods.md)。

## RQ1：更广泛的组织可见性如何改变执行？

### ROMA：递归委派减少

ROMA 的 Atomizer、Planner、Executor、Aggregator 是在不同递归深度复用的功能模块，并非四个管理层级。增加组织视图后，SEAL-0 的平均逻辑任务数从 **5.09 降至 4.76**，展开任务从 **1.49 降至 1.26（−15.8%）**；达到深度三的执行占比由 **23.94% 降至 18.44%**。

FRAMES 的逻辑任务从 **17.55 降至 14.57**，展开任务从 **5.45 降至 4.43（−18.8%）**，平均最大深度从 **2.64 降至 2.45**。两组展开任务绝对差值的配对区间分别为 **[−0.47, −0.02]** 和 **[−1.79, −0.28]**。FRAMES 的平均搜索调用由 **21.06 降至 18.32**，但 47 个配对问题在两种条件下仍全部使用搜索。模型改变了既有递归机制内的任务安排，而非关闭搜索能力。

**完整任务树比较补充了节点数无法表达的结构信息。** 研究重建 **544 棵 SEAL-0 树和 94 棵 FRAMES 树**，使用树编辑距离和按问题分块的 PERMANOVA。SEAL-0 中，条件只解释 **0.20%** 的树变异（未调整置换结果 **p = 0.5308**）；FRAMES 中解释 **1.48%** 的总体变异和 **3.68%** 的题内变异（调整后置换结果 **p = 0.0426**）。因此，减少递归展开是两个任务最清晰的共同响应；完整树形变化在 FRAMES 中有幅度有限的额外证据，不能据此推断两个任务都发生了巨大的整体结构转变。

### TalkHier：固定层级内部的参与方式变化

TalkHier 并未改变固定的监督结构，变化发生在专家参与和单次角色访问内部的工作量。

在 94 个有效配对问题中，Physics 专家的访问次数从 **135 降至 120**，但正常返回的模型调用总数由 **390 增至 653**，每次访问的调用数从 **2.89 增至 5.44**。访问次数下降，并不意味着专家做的工作变少。

Mathematics 专家参与的问题从 **74/94 增至 94/94**，正常返回调用从 **310 增至 627**。执行的内部分析工具调用从 **293 增至 881**，其中 Physics 的分析动作从 **124 增至 421**，Mathematics 从 **128 增至 411**。这些工具是生成局部分析的内部工具，并非浏览、检索或代码执行；其增长说明组织内部分析活动变得更密集，不代表新的外部访问权限。

两位专家贡献正常返回 Token 净增量的 **72.8%**。输出和推理 Token 也随之增长，说明额外工作不只是输入增加了一段组织说明；但这些记录并不能证明每一项额外分析都有价值，或模型显式理解了组织拓扑。

## RQ2：执行变化的计算代价与协作评价

### 任务树规模与计算投入可以不同步

ROMA 在 SEAL-0 中虽然减少递归展开，记录总 Token 只下降 **1.3%**；在 FRAMES 中任务树更小，Token 却**增加 3.7%**。单看任务数不足以推断计算开销。

TalkHier 的正常返回 Token 每题平均增加 **111,523（+65.0%）**，配对 95% 区间为 **[61,256, 161,955]**。94 个问题中，**75 题**增加，**19 题**减少。更多专家工作具有明确的资源代价，但工作量本身不能说明收益；这里的 Token 衡量计算工作量，不等于货币成本。

### 外部规划与通信评分：论文 Table 3

论文利用现有 MARBLE / MultiAgentBench 的规划和通信评价量表，补充评价 ROMA SEAL-0 的完整递归执行记录。共同面板包含 **86 个问题、227 个匹配轮次**，先在每题内平均，再令题目等权。

| 外部 1–5 分评分 | BASE | ORG-DESC | 配对差值 | 配对 95% 区间 |
|---|---:|---:|---:|---:|
| Planning | 4.847 | 4.878 | +0.031 | [−0.031, +0.097] |
| Communication | 4.899 | 4.890 | −0.010 | [−0.076, +0.050] |
| Composite（两项等权均值） | 4.873 | 4.884 | +0.011 | [−0.042, +0.065] |

规划与通信评分均值变化很小，尽管递归执行方式已经改变。评分接近量表上限，且是对转换后轨迹的二次模型评价，并非纯粹跨角色通信的盲评；因此，它提供的是**执行行为与外部协作评价并不必然同步**的补充证据。

## 讨论：组织实现与组织呈现是不同的设计选择

组织实现规定允许哪些成员参与以及怎样路由；组织呈现则规定模型看到怎样的协作说明。即使前者不变，后者仍可能改变实际执行。论文提出：更广泛组织可见性的行为效应可能同时取决于成员原本掌握的信息，以及已有机制允许它们采取的行动；递归架构允许改变委派，固定层级允许改变成员选择和每次访问内的工作。这是与观察一致的解释性假设，并非已被独立验证的因果机制。

ORG-DESC 同时包含拓扑、职责、工作流、澄清以及部分重复内容，比较估计的是整段描述的边际效果，**不能归因于某一单独的信息成分**。核心结论是：**组织信息完整度与实际效用是不同的属性。** 评价组织可见性，需要观察它带来的协作行为、结果和资源投入。

## 离线复核

Python 3.12+ 与标准库即可，不需要模型密钥，不执行新推理或评分：

```sh
uv run --offline --no-project --python python3.12 scripts/reproduce_paper.py
uv run --offline --no-project --python python3.12 scripts/check_repository.py
```

若系统找不到 `python3.12`，可替换为已安装的 Python 3.12 解释器路径；没有 uv 时可直接执行 `python3.12 scripts/reproduce_paper.py`。前者校验历史附件并复算主要汇总，后者检查来源哈希、索引、精选链接和公开敏感文件模式。[复核步骤](docs/reproduction.md) · [本地检查记录](docs/validation.md)。
