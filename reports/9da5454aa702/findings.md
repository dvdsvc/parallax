# 根Atomizer输出与协作过程：完成审计

**最明确的新发现：V2根输出增加几乎全部落在供应商标为reasoning的通道，可见分类说明没有可靠的整体增幅。协作指标已经能按原始证据量化，但现有重复样本尚未给出“V2协作改善超过BASE–BASE波动”的可靠方向证据。** 同时查明递归observer会重复写工具事件，此前按行计数的调用强度需要用本次独立调用口径替换。

本次只读已有归档：历史94题×2条件188次有效运行，加固定15题新增N/R1/R2正常完成88次，共276；协作分析取固定15题所有4组条件的118/120正常完成尝试。V2 R1 q87 provider blocked、BASE R2 q100运行错误不计作0。所有原生正确率评分原样保留；q5/q13保留judge疑点标注。

## 借用哪些轮子

采用[MAST](https://arxiv.org/html/2503.13657)的行为定义与证据标注界限，以及[MultiAgentBench/MARBLE](https://arxiv.org/html/2503.01935)的结果/协作过程分开评价思路；[Guo的组织Agent论文](https://arxiv.org/html/2403.12482)提供组织相关行为分型的参照。两套开源评估代码已按commit固定并保存哈希。原有评估器需要外部模型评分且输入结构不同，本次未执行；用现成sklearn/SciPy/NumPy完成可追溯的代理计算。具体定义、适配与不能推断的内容见methods_and_codebook.md；来源版本见literature/sources.json。

## 1. 根输出到底增加什么

全部276次都成功拆分reasoning计数，最终PLAN/EXECUTE也全与原生树相符。下表是逐题V2/BASE几何平均比与探索性95%题级bootstrap区间；新增重复先题内平均，再题间等权。

| 指标 | 历史94题 | 固定15题新增三组均值 |
|---|---|---|
| 根全部输出token | 1.508 [1.271, 1.799] | 1.341 [1.051, 1.704] |
| 供应商reasoning token | 1.566 [1.298, 1.896] | 1.394 [1.064, 1.817] |
| 非reasoning输出token | 1.045 [0.985, 1.112] | 1.028 [0.967, 1.090] |
| 可见分类说明词数 | 1.081 [0.984, 1.194] | 1.033 [0.944, 1.129] |

历史绝对均值：全部输出1266.26→2791.37 tokens，provider reasoning 1161.81→2680.46，非reasoning 104.45→110.91。净增1525.12中reasoning增加1518.65，占净增99.58%；这是绝对量分解，不是对数比例，也不是reasoning token的因果机制解释。可见最终说明均值56.94→62.49词。历史provider reasoning66题增加/28减少，可见词数52增/41减/1同。

新N/R1/R2三组provider reasoning几何比为1.801/1.135/1.253，后两组各自区间跨1；非reasoning比0.886/1.002/1.234，可见说明词数比0.851/0.985/1.343，方向并不逐批一致。

30例N完整集合的助手定性阅读：两条件各15例均给出任务相关分类理由，均未在可见分类说明中完整复述多个ROMA角色间的组织流转。V2的provider reasoning在历史75/94题提及ROMA，BASE为0/94；这说明生成文本对注入有响应，不能叫理解更深或判断更好。q4 BASE的分类器已提出8/13数值答案并改述数学约束，可见说明的任务性也不保证正确性。供应商reasoning文本不是认知过程的忠实证明。

同条件噪音参照仍限制强结论：完整13题的R1/R2 2对2reasoning平均log差+0.170（约1.186×），仍在BASE四组全局2+2划分的描述范围[−0.295,+0.295]内；不是正式零效应检验。不能宣称已经排除共享批次/重跑波动。

## 2. 必须修正的工具调用口径

归档observer在每个node退出时把共享ctx.tool_invocations切片写出，并重新标task_id/parent_id；父scope重复包括子scope调用。所有276次原记录共有3018条工具事件，仅2182个完全不同的原始invocation。全部别名/时间/原事件行位置保存在tool_invocation_identity_audit.csv，没有删除或改写原归档。

| 历史94题 | BASE记录条数→独立调用 | V2记录条数→独立调用 | 校正后V2−BASE均值及区间 |
|---|---|---|---|
| web_search | 474→430 | 648→421 | -0.096 [-1.511, 1.245] |
| run_python_code | 45→45 | 146→117 | +0.766 [0.149, 1.521] |
| 全部工具 | 697→634 | 1015→723 | +0.947 [-1.277, 3.234] |

V2 R2 q87尤其明显：193条web_search记录实际为22个独立调用，且22个查询均由模型响应恢复并匹配。原来的网页搜索平均+1.851/题经校正变−0.096/题；原来的Python+1.074变+0.766/题。Python在历史仍是次级候选，但新增15题均值+0.722 [-0.133, 2.033]，区间跨0。根token变化不受这项工具事件重复影响。本次没有重算旧111不同环境的工具对比，不能直接把其旧按行计数结果当独立调用。

## 3. 重复搜索有没有稳定下降

固定15题118次正常完成尝试共有658个独立web_search，657个查询已恢复（99.85%）。使用全体恢复查询共享的TF-IDF词表/权重；累计BASE350次搜索中41次exact再次发生、113次达到0.90近似阈值；V2 308次中分别26/70。累计比率不是控制难度与机会后的效应，必须看配对题：

| 新增三组，按题平均 | V2−BASE效应及区间 |
|---|---|
| 独立网页搜索次数 | -1.222 [-3.900, 0.956] |
| 完全相同查询的再次发生次数 | -0.533 [-1.622, 0.222] |
| 相似度≥0.90的再次发生次数 | -0.967 [-2.567, 0.433] |
| 相似查询占比 | -0.063 [-0.169, 0.053] |

0.85/0.90/0.95阈值都报告，没有择优挑选。近似查询占比的-0.063相当于-6.27个百分点，但区间约[-16.91,+5.26]个百分点，当前不稳定。完整13题R1/R2 2对2近似重搜次数均差-0.462，仍在BASE-only描述范围[-1.192,+1.192]内。原文/相似查询重叠只生成候选，核验或不同证据需求可能使再次搜索合理。没有自动标作“无效协作”。

## 4. 结果送达与结果整合要分开

155次Aggregator输入全部成功解析，483个直接完成子结果出现机会全部按原文收到，空结果0。这只证明框架的最后汇总传递完整，不证明模型利用了它们。

从checkpoint恢复335条真实依赖边，335条均有已完成生产者和可定位的消费请求。完整生产结果只在72条消费首包/82条消费任一同节点context中原文匹配。BASE为49/195，V2为33/140。这是显式原文暴露下界，未覆盖摘要、文件、消费子树等途径，不能把其余253条全记为信息丢失。Aggregator输入里的dependencies字段被原生代码置空，不能以该字段断言没有依赖。具体原始请求与边在declared_dependency_exposure.csv和texts/*_cooperation.json。

21例汇总助手审计采用固定选择：N所有9例根汇总，加q19/q87/q100所有有效重复的根汇总去重。可观察到两条件都存在冲突选择、条件放宽、有限时间窗口否定与上游错误传播。例：BASE N q87明确拒绝7胜候选并采用8胜；BASE R2又把>7描述为“slight discrepancy”而接受7胜。V2 R2 q87检索表把同一影片写作1胜/10提名，分析节点改成9胜/14提名，根汇总沿用后者。该矛盾完全来自trace，不需要另外判断BAFTA真实历史，也不能从一个例子推断总体协作更差。

## 5. 目前可以怎样使用这些结果

支持更精确的发现阶段表述：组织知情注入关联根分类阶段的额外provider-reported reasoning输出；增加模型生成投入不自动转化为更长可见说明或已验证的协作改善。它没有证明深层理解机制、全系统效率改善或“没有协作效应”。

对协作主指标，优先保留相对于已送达输入的可核验整合，例如集合交集/阈值/明确依赖事实，以及完成工作后再次检索的证据链；一般文本相似度和组织词用作筛选、操纵响应参照。现有自动计算和21例阅读已经把指标与常见反例具体化；若用作正式论文协作主结果，需要固定标注规则后独立复核并扩展机会样本，不能把这21例助手探索标注当成经验证的全球评分器。
