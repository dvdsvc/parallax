# TalkHier：评分、组织行为与 token 的配对审计

**本次 MMLU-Pro Physics 固定 100 题里，V2 的分数改善很小，正常返回的调用、token 和写分析工具使用却明显增加。排除异常后的诊断结果仍有增量，因此不能把行为差异全归于 API 报错。** 这支持“行为投入增加，但本样本没有显示可靠的准确率收益”的描述；尚不能证明收益在其他任务、模型或更难样本中也有限。

## 研究范围与计数口径

主批次是 `20261006T090617775637Z_mmlu_pro_physics_n100_seed42_tb8192_mc16384_gw16x16`，源提交 `0cddfdc3581bafb969b9d71e68dbeca1c4e6bdde`，上游 TalkHier 固定为 `842a62160bcd326c5f8bb11c6cd1f3da7ced00f6`。官方 MMLU-Pro test Physics 共 1,299 题，seed=42 抽取同一 100 题；样本含 97 道 10 选项、2 道 9 选项、1 道 7 选项题。这里不是完整 MMLU-Pro 成绩，也不是官方 few-shot 推理流程复现。官方评分纯函数固定版本 `f418b116db00b065c2aea046518d8fcf74d39872`，按原始选项顺序把原生整数答案映射 A–J，做精确匹配，无模型评分、无缺失答案随机填充。

BASE/V2 均使用 qwen3.7-flash、temperature=0、enable_thinking=true、thinking_budget=8192、max_completion_tokens=16384、max_tokens 不设置、全部角色。逐题配置除 condition 和 organization_awareness_v2 外一致；源档、评分及全部子档共 304 个归档、40,186 个校验项重新校验通过。API 调用入口原始轨迹中，BASE 的 2,308 次模型启动都没有组织说明，V2 的 3,093 次启动都在首条 system 消息中有同一份组织说明，未发现重复注入。默认模型 seed 未设置；temperature=0 不等于有重复实验下的确定性保证。

主行为统计用双方均完成的 94 对题。调用按 run_id 去重；“正常返回”在此精确定义为 callback status=success、finish_reason 不为 length、并有正文或 tool_calls。**空正文但有有效工具调用的响应保留**，因为这是正常工具调用形态。错误、截断和完全空返回不计入主 token；不从异常文字恢复 usage，不做费用核算。reasoning/cache 是 output/input 的子集，不再加到 total。模型边界正常返回不保证整个图成功，所以另做成功图尝试与无异常题目两项诊断。

API 错误事件与原生根图失败、最终题目失败分开记录。整题失败尝试只数无 langgraph_node 的根 LangGraph chain_error；错误向父子图传播的多个 callback 不重复计数。BASE 的角色从完整 langgraph_checkpoint_ns 的最后一个原生角色识别，避免把嵌套 Physics/Mathematics 全归到 Evaluator Supervisor。

每题正常 total 的中位数为 121,380→206,810；配对 token 差的中位数为 +79,420。75 题增加、19 题减少，无持平；逐题倍率的中位数为 1.81，不能与均值之比 1.65 混称同一个平均倍率。

按问题对进行 20,000 次 bootstrap，seed=20261006，平均 token 差的 95% percentile 区间为 +61,256～+161,955；均值倍率区间 1.31～2.10。它反映当前问题样本下的不确定性，不能替代多次模型运行。

聚合的“每次正常调用 token”从 7,770 到 9,525，约 +22.6%；正常调用数约 +34.6%，两者相乘约等于 total +65.0%。这只是计数分解，单次 token 的变化也受角色构成影响，不能全部解释成同一角色每次多思考。input 包含 V2 额外组织文本，其增加本身不能全部当作行为投入；调用数、output、reasoning 与实际工具执行给出了不同维度的行为证据。两组直接提供的已返回 reasoning 计数都未超过 8192。

排除异常的两个诊断：同样 94 对题，只保留成功根图尝试内的正常返回，均值 126,286→204,129，**+61.6%**；两组均无模型错误、截断/空返回、失败或未结束根图的 50 对题，均值 103,987→199,853，**+92.2%**，44 题增加、6 题减少。这 50 对题的正常调用为每题 17.02→22.90，实际 output_tool 为 2.88→6.68。前者剔除了失败图尝试的正常调用前缀；后者是事后筛选，会改变题目构成，只用于检验“是否全是错误造成”的解释，不能作为无偏主效应估计。

两组 API 边界正常调用的中位延迟分别为 28.9 秒和 33.0 秒；本批次网关记录中 429=0，已结束请求累计限流等待=0。题目总耗时还包含框架、重试与封存。BASE/V2 初始 16+16，BASE 收尾后 V2 上限改 32、实际峰值 29；因此题目 wall time 与总体吞吐只能描述，不能当严格固定并发下的干预延迟效应，也不能推定未测的上游排队。

## 工具与组织流程

Physics 原生 prompt 只配置 tools=[4]，tools.py 的工具 4 是 OutputTool：接收 in_str、返回空字符串，源说明是“write your thoughts”。所以本批次没有启用搜索、Python 计算或环境操作工具。模型还曾生成 1 次未配置的 math_tool 请求；未发现对应实际外部工具执行。实际 tool_start 与模型返回的 tool_calls 分开数，不能将未执行的请求计成执行。

94 对题里，实际 output_tool 从 293 次到 881 次，约 3.01 倍。这主要说明显式写分析的行为增加，不能写成“检索效率提升”或“更多外部证据”。叶节点一次访问可经历 agent→tools→agent 的多次循环，故原生节点访问数、模型调用数和工具执行数是不同层级。

Physics 节点访问从 135 降到 120，但正常调用从 390 升到 653、写分析工具从 124 升到 421：增量集中在单次叶节点访问内的循环，而非只是多次分派 Physics。Mathematics 访问从 93 到 114、正常调用从 310 到 627、工具从 128 到 411。两位专家贡献约 72.8% 的配对净 token 增量。

Mathematics 至少被调用的题数从 74/94 到 94/94，Physics 从 82/94 到 87/94；两位专家都参与的题数从 71/94 到 87/94。Revisor 从 89/94 到 94/94，Evaluator Supervisor 从 93/94 到 94/94。BASE 未经过 Revisor 的完成题为 [9083, 9401, 9665, 9877, 10050]，未经过评估主管的是 [9393]。原生提示要求生成者先行、结束前联系修订者，但图不强制检查；静态组织文本再次说明这些原生要求。它可能同时强化原有工作流要求，不能把差异纯粹归因于“拓扑知识”而完全排除要求显著性或文本长度的影响。

主管只能派给直属成员，每个成员回到所属主管后才选下一成员；专家兄弟之间没有直接派发；主团队等待评估子团队返回。因此这里没有原生并行专家 DAG。跨题任务并发与题内组织并发不能混用。数据描述的是固定非对称层级中的分派、返回、评估与修订，并未改变真实组织拓扑。

## 对当前 claim 的解释边界

较稳妥的表述是：**“在 TalkHier 已有局部角色与直属路由信息、并固定题目和模型预算的条件下，给全部角色增加全局静态组织说明，改变了专家参与及分析工具使用；在该 Physics 样本中，未观察到可靠的准确率提升，却伴随更高的正常返回 token 与调用数。”** 这里的实证重点是投入与成绩脱钩，不应把两个错→对的样本压成“完全没用”。

尚缺同长度同位置的非组织文本对照、拓扑说明与工作流要求复述的拆分、模型重复运行和更能避开天花板的任务。BASE 主主管本来已知道直属成员职责，V2 增量对各角色并不相同；本次是全部角色干预，不能断定哪一角色的全局信息单独造成了变化。无异常题的筛选会影响难度构成，配对未完成题仍需保留。因此目前可作为一个有机制差异的独立迁移案例，不能推出所有组织或所有“组织意识”的普遍结论。

还有一个具体原生提示事实：Physics 配置实际只有 Physics 和 Mathematics 两位评估员，但 Revisor 仍保留“至少四个评估中的三个支持”的指令，专家提示也保留了人物视角/场景解释的跨域步骤。这些原生文字在两组均未改动；V2 又明确说明组织只有这两位专家。组织说明是否让原有指令冲突更显著、是否参与了重复评估与图步数超限，需要按题轨迹验证，目前不能认定为原因。它是比泛泛归责 API 更具体的替代解释，应随实验协议保留。
